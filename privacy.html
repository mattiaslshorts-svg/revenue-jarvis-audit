What this application does

Revenue Jarvis is a local Windows application operated by its owner to produce, review and manage content for the owner's own channels. It is not a public SaaS service and does not currently onboard third-party channel owners. It uses YouTube API Services and Google OAuth.

Information accessed and stored

The application stores OAuth credentials and refresh tokens locally, channel IDs/names/handles, upload metadata and remote video IDs/status, technical audit logs and local video hashes. Optional code can obtain video/channel statistics, YouTube Analytics engagement data and estimated revenue. Optional API-key trend research exists but is not configured in this installation. Video files, scripts and rights evidence are stored locally.

OAuth tokens authorize Google API requests; they are not included in the static audit pages or evidence PDF. Local JSON token files are not application-encrypted; Windows account/file access controls protect the installation. The operator must restrict access to the machine and its backups.

Uploads and recipients

Only explicitly reviewed videos may enter the private queue when its separate switch is enabled. The API request sends the approved video and metadata to Google/YouTube with private visibility. Public publication is currently disabled. A Founder can separately use YouTube Studio. Revoking access or deleting local records does not delete videos already held by YouTube.

There is no implemented sale or advertising-data brokerage feature. The inspected YouTube transport sends credentials to Google's token/API endpoints and uploads to YouTube; it does not send OAuth tokens to other publishers. Optional non-YouTube content providers exist separately. Their configuration and use require the operator's review; this policy does not claim all application activity is offline.

Retention and deletion — current limitation

The current implementation retains local credentials, API data and logs until manually removed. It does not implement an automatic retention timer, periodic authorization/deletion sweep or a complete in-app deletion workflow. This is an outstanding compliance gap, not a promise of automatic deletion. Before submitting the audit, the operator must define and implement the applicable retention and deletion process and update this draft truthfully.

For a deletion request contact [CONTACT EMAIL] (FOUNDER_INPUT_REQUIRED; not yet an operational contact route). The operator must account for local SQLite databases, JSON evidence, exports and backups. Removing a token alone does not erase stored API data. Removing local state must be done with the runtime stopped and must not enable accidental re-upload by discarding duplicate reservations.

Revoking Google access

The owner can revoke access through https://myaccount.google.com/connections . After revocation, future refresh/API calls may fail and uploads stop; existing local data is not automatically purged. Reauthorization uses the local OAuth flow and must verify the same permanent channel ID. Google handles its own data under https://policies.google.com/privacy . YouTube's Terms apply: https://www.youtube.com/t/terms .
